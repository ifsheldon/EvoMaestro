An excellent way to improve the routing performance is to explicitly account for the **transmission delay** (`payload_size / capacity`) which was previously ignored in the latency calculation.

By introducing a second, capacity-sensitive routing mode (Dijkstra pass) per server, we can generate alternative paths that avoid low-capacity bottlenecks. During the assignment phase, we evaluate both the standard path and the high-capacity path for each task source, calculating the true latency as `base_latency + payload_size / capacity`. This allows tasks with large payloads to dynamically select the high-capacity routes, while small tasks can still take the shorter, lower-energy routes.
