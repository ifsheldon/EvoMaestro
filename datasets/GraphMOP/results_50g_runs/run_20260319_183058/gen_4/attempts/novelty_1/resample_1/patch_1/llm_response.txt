<DESCRIPTION>
The proposed modification improves the task routing by using a more theoretically sound marginal cost heuristic. 

1.  **Adaptive Dijkstra Weighting**: Instead of a fixed weight, the Dijkstra search now uses a weight that balances latency and energy based on the specific task's arrival rate and payload size: `weight = arrival_rate * (base_latency + payload_size * energy_cost)`. This represents the task's marginal contribution to the total system travel latency and routing energy.
2.  **Marginal Delay Modeling**: The server selection now uses an M/M/1 queueing model to calculate the marginal increase in total system delay caused by adding a task to a server: `marginal_delay = new_load / (service_rate - new_load) - old_load / (service_rate - old_load)`. This captures the non-linear increase in latency as a server approaches saturation.
3.  **Marginal Energy Modeling**: The server selection also accounts for the marginal increase in compute energy and the idle power cost of activating a new server.
4.  **Efficiency**: Dijkstra is run once per task source (instead of once per source-server pair), which is more efficient and allows for a more thorough search of the solution space.
5.  **Task Ranking**: Tasks are ranked by their total potential impact (load and routing) to prioritize the assignment of more demanding tasks.
