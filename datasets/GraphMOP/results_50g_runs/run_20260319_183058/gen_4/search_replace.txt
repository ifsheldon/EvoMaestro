<DESCRIPTION>
This improvement optimizes task routing by:
1.  **Pre-calculating shortest paths**: Instead of running Dijkstra for every task-server pair ($T \times S$), we run it once per server ($S$). This significantly improves efficiency.
2.  **Using a combined cost metric**: Dijkstra now uses a weight that balances transmission latency and routing energy.
3.  **Theoretically-grounded server selection**: Servers are selected based on the marginal increase in total system latency (transmission + M/M/1 queueing delay) and total system energy (routing + compute energy).
4.  **Improved task prioritization**: Tasks are processed in descending order of their total computational load to ensure that the most demanding tasks are assigned to the most efficient servers.
</DESCRIPTION>
