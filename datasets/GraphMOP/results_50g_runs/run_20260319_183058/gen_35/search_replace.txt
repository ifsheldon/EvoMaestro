<DESCRIPTION>
This edit improves assignment quality in two coordinated ways.

First, it makes the regret ordering explicitly scarcity-aware. The current construction phase prioritizes tasks mostly by the gap between their best and second-best placements, with a demand boost. That still allows flexible tasks to consume scarce low-load server capacity too early. The new priority computes how many candidate servers remain “safe” for each source under the current partial assignment: below the soft-utilization target and with modest queue-cost increase. Sources with fewer safe options get boosted, while highly flexible sources are slightly deprioritized. This better preserves rare good placements for harder tasks.

Second, it slightly strengthens queue/activation tradeoffs by using a more M/M/1-like queue term in server_state_cost and a somewhat more latency-sensitive path set. This is intended to reduce placements that look cheap initially but create avoidable queueing pressure, while still keeping energy competitive.

These are targeted changes only within the evolve block and preserve the required output format and validity behavior.

        opts = []
        for server, cand in candidates[src].items():
            delta = assignment_delta(src, cand, server_load)
            opts.append((delta, server, cand))
        opts.sort(key=lambda x: (x[0], len(x[2]["path"])))
        return opts

    def scarcity_stats(src, opts):
        safe_count = 0
        modest_count = 0
        best_score = opts[0][0]
        for score, server, cand in opts:
            mu = max(cand["service_rate"], 1e-9)
            new_load = server_load[server] + cand["demand"]
            util = new_load / mu
            queue_bump = server_state_cost(server, new_load) - server_state_cost(server, server_load[server])

            if util <= SOFT_UTIL:
                safe_count += 1
            if util <= min(HARD_UTIL, SOFT_UTIL + 0.04) and queue_bump <= 0.55:
                modest_count += 1

        near_best_count = 0
        near_best_band = 0.20 + 0.10 * best_score
        for score, _, _ in opts:
            if score <= best_score + near_best_band:
                near_best_count += 1

        return safe_count, modest_count, near_best_count
