<DESCRIPTION>
The previous approach used an inefficient O(T*S) path-finding strategy and a fixed heuristic that didn't scale with task-specific payloads or non-linear queueing costs. 

My new algorithm, `marginal_cost_routing`, introduces the following improvements:
1. **O(S) Complexity**: It precomputes shortest paths using Dijkstra beginning from each server node once, rather than from each task source. This drastically reduces runtime for large source counts.
2. **Marginal Incremental Costing**: The server selection score now calculates the marginal latency increase using the M/M/1 queuing model ($1 / (\mu - \lambda)$), which accounts for the exponential delay increase as server capacity is reached.
3. **Payload-Aware Path Heuristic**: Edge weights in Dijkstra are now balanced using the average payload size ($latency + \alpha \cdot energy\_cost \cdot payload_{avg}$), ensuring paths are optimized for both time and energy.
4. **Dynamic Energy Scoring**: It weights the energy increase (routing energy + dynamic compute energy) against latency to ensure a multi-objective balance, leading to lower overall scores.
