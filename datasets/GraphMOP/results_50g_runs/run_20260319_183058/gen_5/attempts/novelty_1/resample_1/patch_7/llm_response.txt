<DESCRIPTION>
The previous implementation performed an expensive Dijkstra search for every source-server pair and used a simplified server score that ignored the non-linear impact of queueing. 

My new algorithm, `marginal_cost_routing`, introduces these optimizations:
1. **O(S) Path Precomputation**: Instead of $O(T \times S)$ path searches, it runs Dijkstra from each server node once ($O(S \times E \log N)$). Because the graph is undirected, $dist(server, source) = dist(source, server)$, drastically reducing computation time.
2. **Marginal Total Cost Analysis**: For server assignment, it calculates the marginal increase in total system latency and energy. It uses an M/M/1 queueing model derivative ($1/(\mu - \lambda)$) to account for how a new task affects the latency of its own flow.
3. **Task-Load Ranking**: Heavy tasks (high arrival rate $\times$ high compute) are prioritized in the greedy assignment phase to ensure efficient resource utilization.
4. **Multi-Objective Path Weighting**: Dijkstra weights combine base latency and energy cost (scaled by average payload), ensuring the precomputed paths are optimized for both metrics simultaneously.
