The current approach uses a simple heuristic and a fixed-weight Dijkstra that doesn't account for task-specific payload sizes or the non-linear nature of queueing delays. 

My new algorithm improves this by:
1.  **Accurate Objective Modeling**: It uses a marginal cost function derived from the system's total latency and energy. This includes a more realistic M/M/1 queueing delay model ($V / (\mu - V)$) and compute energy ($P_{dyn} \cdot V / \mu$).
2.  **Task-Specific Path Optimization**: It precomputes shortest paths from each server using a combined weight ($latency + energy\_cost \times avg\_payload$) to balance the two objectives during routing.
3.  **Dynamic Load Balancing**: Instead of a fixed utilization cap, it uses the marginal increase in total system latency (including the impact on all tasks already at a server) to make assignment decisions.
4.  **Efficiency**: By running Dijkstra from the few server nodes instead of many task sources, it significantly reduces computational overhead while maintaining high accuracy.
