<DESCRIPTION>
The original algorithm uses a fixed-weight Dijkstra and a simple heuristic for server assignment that doesn't fully account for the non-linear impact of server load or the specific arrival rates of tasks. 

My new algorithm, `marginal_cost_routing`, improves performance by:
1.  **Marginal Cost Analysis**: It models the assignment of each task as a marginal increase in total system cost (latency + energy). This includes the M/M/1 queueing delay impact on all tasks at a server, not just the new task.
2.  **Efficient Path Precomputation**: It runs Dijkstra from each server node once, using a balanced weight ($base\_latency + 0.3 \cdot energy\_cost$) to find optimal paths for both objectives.
3.  **Dynamic Load Management**: Instead of a hard utilization cap, it uses a steep penalty function for high utilization, allowing for better load balancing under heavy traffic.
4.  **Energy Optimization**: It accounts for the marginal routing energy (based on payload size), dynamic compute energy, and the idle power cost of activating a server.
