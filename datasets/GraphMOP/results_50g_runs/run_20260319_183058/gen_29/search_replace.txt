An excellent way to improve the performance is to introduce a more diverse set of candidate paths and to compute the exact marginal contribution of each assignment to the global objective function.

1. **Candidate Path Generation**: Instead of using just two fixed trade-offs with a nominal payload, we can use four fixed modes that blend latency, energy, and capacity using the actual average and maximum payloads. Additionally, we introduce an **adaptive mode** per server that slightly increases the energy weight for servers with high dynamic power consumption.
2. **Exact Marginal Score**: The previous marginal score calculation approximated the queueing delay derivative and missed multiplying the path latency by the task arrival rate. We can replace this with the exact difference in total system queueing delay and total system energy (including idle power penalties when a server is first activated).
3. **Local Search Stability**: When tentatively removing a task's load during local search, floating-point inaccuracies can cause the server load to become slightly negative. Clamping it to zero ensures the idle power penalty is correctly re-evaluated.
