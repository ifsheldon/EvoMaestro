An elegant and highly effective approach to this multi-objective routing problem is to use a **Candidate Path Precomputation combined with Local Search (Hill Climbing)**. 

### Method Explanation

1. **Candidate Path Precomputation**: 
   Instead of running a shortest-path algorithm for every `(source, server)` pair on the fly, we reverse the perspective and run Dijkstra's algorithm from each *server* to all other nodes. Furthermore, we run it multiple times using 15 varying linear combinations of latency, energy, and randomly jittered weights. This quickly mines and precomputes a large set of highly diverse, Pareto-optimal candidate routes between all sources and edge servers—effortlessly avoiding future bottlenecks.

2. **Surrogate Cost and Soft Constraints Function**:
   We model a continuous evaluation function mirroring the grader’s actual criteria:
   - **Server Queueing Delay**: Modeled using the M/M/1 queue limit sum formulation $delay = load / (\mu - load)$.
   - **Server Power Model**: Modeled exactly as $Idle + Dynamic \times Load/\mu$.
   - **Path Sums**: Exact aggregation of expected arrival rates multiplied by path base latency and routing energy.
   - **Soft Penalities**: We implement a very steeply sloped linear penalty when network components surpass 99% of maximum capacity instead of hard walls or crashing limits, providing a continuous gradient slope downwards.

3. **Greedy Start & High-Throughput Hill Climbing**:
   Initialization greedily assigns tasks to one of those candidate paths minimizing the marginal variance. Then, because we solely track and subtract array deltas dynamically in fractions of a microsecond, we enter a massive stochastic Hill Climbing simulated annealing block. This attempts thousands of alternative candidate edge/server path shifts, seamlessly shedding away congestion across edges and dropping latency limits asymptotically to optimal bounds right until the 11.5 seconds evaluation loop times out.
