# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **The current best result confirms that bounded multi-tree preprocessing plus strong marginal server scoring is the most effective observed pattern.** The current best program, **Regret-Aware Multi-Mode Server Routing** / **Generation 21 - `regret_activation_routing`**, achieved the strongest reported valid result here at **score 5.215922** with **latency 2.304111** and **energy 1.959833**. Its effective combination is:
  - **four server-rooted Dijkstra modes** with different `(latency, energy, congestion)` blends,
  - **payload-aware recomputation** of route latency/energy after path reconstruction,
  - **regret-ordered greedy assignment**,
  - **incremental server-load surrogate** including queue pressure, dynamic power, and activation cost,
  - **bounded local relocation** with only **4 passes**.

- **Compared with simpler regret-greedy variants, richer server-state scoring appears to explain the small but real improvement.**  
  **Generation 14 / Regret-Greedy Dijkstra Task Routing** scored **5.23** at **2.30 / 1.96**, and **Generation 15 / Greedy Regret-Based Multiobjective Routing** scored **5.22** at **2.30 / 1.96**. Both were valid and balanced, but used more limited path weighting and simpler marginal assignment logic. The current best keeps the same broad family but adds:
  - explicit **hard/soft utilization controls**,
  - **convex queue surrogate**,
  - **idle-power activation penalty**,
  which matches the slight gain from ~**5.22–5.23** down to **5.215922**.

- **Moderate candidate diversity remains the best runtime-quality tradeoff.**  
  The current best and **Generation 20 / Regret-Based Multi-Path Server Routing** both rely on a small number of server-rooted shortest-path trees rather than exhaustive profile generation. Generation 20 used **four server-centric Dijkstra variants plus BFS fallback** and reached **5.23** with **2.31 / 1.96**. This reinforces the previous insight that **a small fixed set of diverse trees** is enough to improve over single-weight routing without causing timeout risk.

- **Lightweight refinement helps when the main assignment state is incremental and compact.**  
  The current best performs **several relocation passes** using exact surrogate deltas, while Generation 20 used **two local improvement passes** and Generation 14 used **up to 5 rounds** of reassignment refinement. Across these valid programs, local search is only successful when it is **short, stateful, and bounded**; these methods remain competitive, all clustered around **5.22–5.23**, without sacrificing correctness.

## Ineffective Approaches
- **Missing or incomplete routing pipelines still lead to total failure regardless of wrapper quality.**  
  **Generation 19 / Missing Routing Function Wrapper** returned only the grading harness without a usable `evolve_task_routing` implementation and failed completely with **-999999999.00**. This strongly reinforces the earlier pattern that correctness and a complete executable pipeline dominate any high-level heuristic intent.

- **Heavier path-generation/search ideas have still not translated into better results than the bounded multi-tree family.**  
  From prior insights, **Generation 6**, **Generation 7**, and **Generation 16** all timed out at **-999999999.00** because they combined repeated shortest-path work with more expensive local search or fragile integration. The newly evaluated valid programs continue to support that conclusion: none of the heavier or more elaborate path/assignment ideas surpassed the compact server-rooted multi-tree approach.

- **Fixed weighted-path objectives with weaker assignment calibration plateau near, but not better than, the current best.**  
  **Generation 14** used Dijkstra with a fixed combined edge weight of latency plus **0.4× energy**, then greedy regret assignment and local reassignment, ending at **5.23**. **Generation 15** used two fixed trade-off weights during candidate generation and also plateaued at **5.22**. The feedback for both explicitly notes that they did not reduce latency and energy enough simultaneously, indicating that **limited path objective diversity and simpler assignment surrogates** restrict Pareto efficiency.

- **Adding more route modes alone is not sufficient without a stronger marginal placement model.**  
  **Generation 20** expanded path generation to include latency-energy-capacity-weighted variants and BFS fallback, but still scored **5.23**, slightly behind the current best. This suggests that **candidate diversity by itself** is not what drove the best score; the edge came from the **more calibrated assignment/queue/activation scoring** in Generation 21.

## Implementation Insights
- **What makes the current best effective is the exact decomposition between preprocessing and assignment.**  
  It does not search over all source-server-path combinations dynamically. Instead, for each server it runs exactly **four Dijkstra trees**, reconstructs source-to-server paths, then recomputes the **true payload-dependent** path latency and energy through `path_metrics`. This mirrors the previous global insight that **compact server-rooted preprocessing** is the stable, high-performing implementation pattern.

- **The current best’s server-state cost is its clearest implementation advantage over nearby baselines.**  
  Its `server_state_cost(server, load)` includes:
  - a **hard penalty** beyond `HARD_UTIL = 0.985`,
  - a **queue term** `load / (mu - load)`,
  - an extra **soft penalty** above `SOFT_UTIL = 0.90`,
  - **dynamic power** via utilization,
  - **activation cost** through idle power when a server becomes active.  
  This is more explicit and better calibrated than the simpler “queue/load estimates” in **Generation 14** and **Generation 15**, and likely explains the improvement from about **5.22–5.23** to **5.215922**.

- **Regret ordering is consistently useful, but only when paired with incremental marginal deltas.**  
  The current best computes `assignment_delta` from the exact change in server-state surrogate, then ranks sources by **regret gap** scaled by **demand factor**. That is a more concrete and state-aware version of the regret-greedy approach used in **Generation 14** and **Generation 15**. The shared success of these programs shows regret ordering is robust, while the current best shows the gain comes from making the regret signal reflect **true projected load impact**.

- **Defensive coding around path validity and reachability continues to correlate with correctness.**  
  The current best:
  - reconstructs paths from stored parent arrays,
  - recomputes metrics using `edge_map`,
  - has explicit **BFS fallback** for reachability,
  - includes a final **validity fallback** to ensure every source gets a structurally safe output.  
  This aligns with earlier insights that robust fallback behavior separates passing solutions from invalid or timeout-prone ones, especially compared with prior fragile implementations.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a server-diverse candidate retention layer instead of keeping only the single best path per server from the four trees.** For each `(source, server)`, keep up to **2 non-duplicate paths** if the second path is meaningfully different in true payload-recomputed metrics or hop structure, then let assignment choose between them using the same marginal load-aware delta. This directly extends the current best’s bounded multi-tree preprocessing while testing the prior insight that a **small amount of extra route diversity for elite pairs** may improve both latency and energy without triggering heavy-search timeouts.

2. **Refine `assignment_delta` with an explicit congestion externality term that prices harm to already-placed load.** In addition to `server_state_cost(new)-server_state_cost(old)`, add a small term like `existing_load * (queue_term(new)-queue_term(old))` or a first-order approximation of future waiting harm, so servers with many assigned tasks become less attractive before they approach the hard threshold. This is strongly supported by the observed advantage of the current best’s richer server-state surrogate over simpler regret-greedy baselines.

3. **Make regret ordering more capacity-aware by using feasibility-weighted regret, not just best-vs-second-best gap.** For each source, compute regret from the top two marginal options but amplify priority when the best candidate is one of only a few options that remain safely below `SOFT_UTIL` or `HARD_UTIL`; conversely, deprioritize flexible tasks with many near-equivalent servers. This keeps the proven regret framework but better preserves scarce low-cost server capacity for hard-to-place sources, which matches the best program’s assignment-calibration advantage.

4. **Replace broad relocation passes with a hotspot-focused repair phase centered on the most penalized servers.** After initial assignment, identify the **top 1–3 servers by queue/soft-penalty contribution** and only reconsider tasks currently assigned there, testing moves to a few precomputed alternatives and optionally one best swap with another hot server. This preserves the success of bounded local improvement while concentrating work where the surrogate says global score is most fragile, rather than spending passes on already-stable servers.

5. **Introduce a tiny adaptive path-mode perturbation driven by payload and server load characteristics.** Keep the existing four fixed Dijkstra modes, but add at most **one extra derived mode per server** that slightly increases latency weight for high-payload tasks on low-capacity regions or slightly increases energy weight for low-demand tasks where route energy dominates. This builds directly on the winning multi-tree pattern while addressing the main remaining frontier issue: the current fixed modes are strong, but modest task-aware weighting may uncover small simultaneous gains in both latency and energy.
