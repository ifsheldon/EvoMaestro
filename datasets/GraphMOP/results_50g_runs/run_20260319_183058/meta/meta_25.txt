# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **The strongest observed pattern remains the bounded multi-tree, server-rooted preprocessing used by the current best program, Generation 21 / `regret_activation_routing`, at score `5.215922` (`latency 2.304111`, `energy 1.959833`).** Its specific winning implementation choices are visible in the provided code:
  - exactly **4 Dijkstra modes** with different `(latency, energy, congestion)` blends,
  - **payload-aware recomputation** of route latency/energy after path reconstruction via `path_metrics`,
  - **regret-aware task ordering** using the gap between best and second-best server options,
  - **incremental server-state marginal deltas** with queue pressure, dynamic power, and activation cost.  
  This combination still outperforms the nearby valid baselines clustered around `5.22–5.31`.

- **Richer marginal server scoring produced the clearest improvement over simpler greedy server selection.** Compared with:
  - **Generation 25 / `marginal_dualobjective_server_trees`** at **5.22** (`2.30 / 1.96`),
  - **Generation 27 / `restricted_server_focused_repair`** at **5.23** (`2.31 / 1.96`),
  - **Generation 24 / `server_diverse_multicriteria_routing`** at **5.31** (`2.33 / 1.97`),
  - **Generation 5 / `marginal_cost_routing`** at **5.30** (`2.33 / 1.97`),  
  the current best’s advantage comes less from having more path candidates and more from a **better-calibrated assignment objective**: hard overload penalty, soft utilization penalty above `0.90`, queue term `load / (mu - load)`, dynamic power term, and first-activation idle-power cost.

- **Moderate candidate-path diversity continues to help, but only when tightly bounded.** Valid competitive programs all use a **small fixed set of server-rooted shortest-path trees**:
  - Generation 21: **4 modes**, best score `5.215922`
  - Generation 24: **multi-alpha Dijkstra trees**, score `5.31`
  - Generation 27: **3 modes + one penalized alternative**, score `5.23`  
  This reinforces the prior pattern that **compact route diversity is enough to beat single-weight routing**, while remaining runtime-safe.

- **Short, bounded local improvement remains a useful finishing step when state is incremental.** The current best uses **4 relocation passes** based on exact surrogate gains; Generation 27 also uses a restricted repair pass and stays competitive at **5.23**. This matches prior evidence that **small relocation loops help only when the candidate set and server-load state are already compact and maintained incrementally**.

## Implementation Insights
- **What makes the current best program effective is the exact split between cheap preprocessing and stateful assignment.**  
  In the provided code, it:
  - builds the graph once,
  - runs **4 server-rooted Dijkstra trees per server** using fixed mode tuples,
  - reconstructs source-server paths from stored parent arrays,
  - then recomputes true path latency/energy with payload and capacity using `path_metrics`.  
  This avoids expensive online path search during assignment while still scoring candidates using more realistic payload-dependent route costs.

- **The current best’s `server_state_cost` is its most distinctive implementation advantage.**  
  Its surrogate includes:
  - **hard infeasibility pressure** at `HARD_UTIL = 0.985`,
  - **soft quadratic pressure** above `SOFT_UTIL = 0.90`,
  - **queue growth** via `load / (mu - load)`,
  - **dynamic power** proportional to utilization,
  - **activation cost** through idle power only when a server becomes active.  
  This is more detailed than the summaries for Generations 25 and 27, which mention queue-delay and energy proxies but not as explicit a hard/soft-utilization structure. That additional calibration is the most plausible source of the small but repeatable score edge.

- **Regret ordering is implemented in a more state-aware way than in weaker greedy baselines.**  
  The current best does not simply sort by task size or base score. It recomputes `assignment_delta` using current `server_load`, then ranks unassigned tasks by **regret gap** between top two options, scaled by demand. This is a stronger version of the regret-greedy pattern already seen in earlier successful programs and aligns with the prior insight that **regret is useful only when based on true marginal load impact**.

- **Defensive path-validity handling remains strongly associated with correctness.**  
  The current best includes:
  - parent-based path reconstruction,
  - `edge_map`-based metric recomputation,
  - **BFS reachability fallback** when candidate generation fails,
  - a final per-source validity fallback to guarantee structurally safe outputs.  
  That coding style matches the earlier correctness pattern: robust fallback behavior separates the competitive valid programs from incomplete or fragile ones like Generation 23.

This continues the prior pattern that **bounded multi-tree + load-aware assignment** is not just competitive, but effectively the only reliably high-performing and validation-safe approach seen so far.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Keep the 4 server-rooted Dijkstra trees, but retain up to 2 path candidates per `(source, server)` instead of only the single best deduplicated path.** Select the second path only if it is structurally different enough from the best one, such as different hop sequence or a noticeable payload-recomputed latency/energy tradeoff. This directly extends the winning bounded multi-tree pattern while testing whether a tiny amount of extra per-server route diversity can improve assignment quality without losing runtime safety.

2. **Augment `assignment_delta` with a small congestion externality term that penalizes adding load to already busy servers before they hit soft utilization.** A practical mutation is to add something like `beta * old_load * (queue_term(new) - queue_term(old))` or a first-order approximation of extra waiting harm imposed on existing tasks. This is well supported by the best program’s advantage coming from richer marginal server scoring, and it may improve both latency and energy by steering load away from emerging hotspots earlier.

3. **Make regret ordering explicitly scarcity-aware, not just best-vs-second-best gap aware.** For each source, compute how many candidate servers remain below `SOFT_UTIL` or below a modest queue-cost threshold, then boost priority for tasks with few safe options and reduce priority for flexible tasks with many near-equivalent placements. This preserves the current best’s strong regret framework while better protecting scarce low-cost server capacity for harder assignments.

4. **Replace uniform relocation passes with hotspot-focused repair centered on the 1–3 most penalized servers.** After initial assignment, rank servers by current `server_state_cost` contribution or queue/soft-penalty intensity, then only reconsider tasks on those servers against a short list of precomputed alternatives, optionally including one swap move. This builds on the proven value of bounded local search, but concentrates effort where the surrogate says global score is most vulnerable.

5. **Add at most one extra adaptive path mode per server, derived from local task/server characteristics, rather than globally increasing route-mode count.** For example, generate one additional Dijkstra weighting that slightly increases congestion and latency emphasis for high-payload tasks or slightly increases energy emphasis for low-demand tasks when route energy dominates. This is a cautious extension of the current best’s fixed 4-mode preprocessing and is more promising than broad path diversification because recent results show assignment calibration wins unless route additions are tightly bounded and targeted.
