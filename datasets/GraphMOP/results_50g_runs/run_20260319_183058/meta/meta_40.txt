# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Replace the current queue term with an exact server-state delta objective during assignment.** Instead of scoring with `arr_rate * q_delay_new + projected_arr * (q_new - q_old)`, compute a fuller marginal queue contribution such as `projected_arr_new/(mu-new_load) - projected_arr_old/(mu-old_load)` or another exact delta of the end-of-pass queue formula. This directly extends the strongest validated pattern—load-aware marginal assignment—and is the most likely way to improve the tiny remaining calibration gap without changing the overall architecture.

2. **Add dynamic regret-based task selection on top of the current multi-pass greedy search.** Every few assignments, recompute for a small active pool of unassigned tasks the gap between their best and second-best `(server, tree)` choices under current projected loads, then assign the highest-regret task next. This preserves the current best program’s strong marginal scorer while borrowing the proven Generation 21 idea that assignment order should react to evolving saturation rather than stay fixed.

3. **Compress route candidates per `(source, server)` to a tiny non-dominated set instead of iterating all distinct trees blindly.** After building the server-rooted trees, reconstruct each source-to-server option and keep only the best route plus at most one alternate if it is genuinely path-distinct and offers a meaningful latency/energy tradeoff not dominated by the first. This follows the evidence that compact, high-quality path diversity helps, while broad candidate expansion by itself has not beaten the top score band.

4. **Add a very small repair phase focused only on overloaded or high-derivative servers.** After the greedy assignment, rank servers by utilization or queue sensitivity `1/(mu-load)^2`, then try relocating tasks from the top 1–3 hottest servers to their next-best precomputed alternatives using the same marginal score; optionally test a bounded one-swap move for tasks with near-tied choices. This is a targeted extension of the winning greedy design and avoids the broad local-search machinery that previously underperformed.

5. **Make route preprocessing slightly more adaptive by adding one conditional fourth tree only for clearly energy- or congestion-sensitive cases.** For servers attracting many high-arrival or high-compute tasks, generate one extra Dijkstra tree with a stronger mixed weight such as `lat + w_e*eng + gamma/capacity`, and only retain it if it yields new non-dominated source paths. This respects the successful “cheap offline precompute + richer online assignment” structure while testing a narrow, evidence-consistent way to improve routing quality without exploding candidate count.
