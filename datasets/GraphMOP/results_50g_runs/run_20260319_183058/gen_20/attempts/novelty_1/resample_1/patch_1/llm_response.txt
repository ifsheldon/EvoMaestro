<DESCRIPTION>
This edit makes two targeted improvements:

1) **Increase path candidate diversity per server** by adding a 4th server-rooted shortest-path tree with a stronger capacity/congestion-aware blend. This preserves the fast precompute pattern while giving the assignment stage more robust alternatives in graphs where hop latency and edge energy trade off differently under capacity constraints.

2) **Make idle-power scoring activation-aware instead of per-task additive**. The previous scoring charged idle cost for every assigned source, which can distort energy optimization. Idle power is a server-level fixed cost, so this update charges it mainly when a server is newly activated (and mirrors this in local search), improving both latency-energy balance and assignment stability.

Additionally, a small tie-break fix in regret ordering prioritizes harder-to-place sources when regrets are equal.
